# Установка и окружение

## Клон

Общий порядок (папка скиллов агента, хук, автор, стоп-лист, обновление) —
соседний скилл skill-skill, `knowledge/40_СРЕДА/40-01`. Для этого набора:

```bash
git clone https://github.com/RungeKut/MCU-Skill.git "<папка скиллов>/mcu"
cd "<папка скиллов>/mcu"
git config core.hooksPath ../skill-skill/hooks
git config user.name  "<публичное имя>"
git config user.email "<публичный адрес>"
git config mcu.project "<папка проекта>"   # необязательно: её имя — в стоп-слова
python tools/check_docs.py                 # до «Расхождений нет»
```

Свой стоп-лист набора — `tools/stoplist.txt` (локальный, в `.gitignore`),
вдобавок к общему skill-skill; приметы нового изделия — туда до первого
коммита (40-02).

## Что нужно

Python 3.11+ (проверено на 3.12 и 3.13), только стандартная библиотека —
`pip install` не нужен. Нет Python:
`winget install --id Python.Python.3.13 --scope user --silent`.

| Что | Где берётся | Как находит mcukit |
|---|---|---|
| SEGGER J-Link Software | segger.com, пакет «J-Link Software and Documentation» | `MCUKIT_JLINK` → свежая `Program Files\SEGGER\JLink*` |
| STM32CubeProgrammer | st.com или внутри STM32CubeIDE | `MCUKIT_STLINK` → 40-03 |
| arm-none-eabi-gcc | Arm GNU Toolchain или внутри STM32CubeIDE | `MCUKIT_GCC` → PATH → Arm GNU Toolchain → `C:\ST\STM32CubeIDE_*\...\gnu-tools-for-stm32*\tools\bin` |
| make | PATH или внутри STM32CubeIDE | `MCUKIT_MAKE` → PATH → `...\externaltools.make*\tools\bin\make.exe` |

Хватает одного зонда — набор находит то, что есть. `MCUKIT_*` задают
только пути к программам на машине, где поиск их не нашёл; путь к самому
набору переменными не задаётся (skill-skill, 30-01). Драйвер ST-Link без
сайта ST — 30-10.

Рабочие папки заданий: `MCUKIT_WORK`, иначе `%LOCALAPPDATA%\Temp\mcukit`.
Там лежат файлы команд, журналы J-Link (`jlink.log`) и копии проектов —
первое место, куда смотреть при сбое.

## Проверка программ

То, что раньше печатал установщик, — одной командой из корня набора, к
плате не подключается:

```bash
python -c "import mcukit as mk; mk.utf8_console()
for n, f in (('J-Link', lambda: mk.jlink_dir() + ' ' + mk.jlink_version()),
             ('ST-Link', lambda: mk.stlink_cli() + ' ' + mk.stlink_version()),
             ('GCC', lambda: mk.gcc_bin() + ' ' + mk.gcc_version()),
             ('make', mk.make_exe)):
    try: print('OK ', n, f())
    except Exception as e: print('НЕТ', n, e)"
python tests/test_build.py      # сборка шаблона без железа
```

Зонд — `mk.probe()` / `mk.stlink.probe()`: к чипу не подключаются.

## Шаблон проекта: как run.py находит набор

Шаблон копируется в папку проекта, а она может лежать где угодно.
`templates/*/run.py` ищет корень скилла mcu (папку с `SKILL.md` и
`mcukit/`) по порядку:

1. `python run.py --kit "<корень набора>"`;
2. `KIT = r"<корень набора>"` в `project.py` — вписывается при
   копировании шаблона: агент знает корень, это папка `SKILL.md`;
3. вверх от папки проекта: сам набор (шаблон запущен на месте) или
   соседний скилл `mcu` (проект лежит в папке скиллов).

Не нашёл — ошибка с подсказкой; переменные окружения не читаются. Проверка
на `SKILL.md` нужна: `%LOCALAPPDATA%\Temp\mcukit` — рабочая папка того же
имени, и поиск вверх из временной папки без неё находил её.

## Подключение из другого набора

```python
import os, sys
ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))  # корень своего набора
sys.path.insert(0, os.path.join(os.path.dirname(ROOT), "mcu"))
import mcukit
```

Глубину `dirname` — по месту файла. Так `mcukit.gcc_bin()` берёт соседний
набор для VisualState (на его стороне — не переведено, не проверено).

## Зонд с именем SAM-ICE

`ShowEmuList` показывает `ProductName: SAM-ICE`, железо J-Link V9.50,
лицензии `RDI,FlashBP,FlashDL,JFlash,GDB`. Официально SAM-ICE — вариант
J-Link для чипов Atmel/Microchip. Этот экземпляр подключился к GD32F470,
записал и прочитал флеш без ограничений. Другой экземпляр SAM-ICE может
вести себя иначе — проверять.

## История

До 2026-10-28 набор ставился установщиком (`setup.ps1`,
`Install-skill.bat`): junction из папок скиллов Claude Code, Kimi Code и
opencode в `<корень>\skill`, переменная с путём к клону, свой хук и
стоп-лист. Отказались: клон теперь и есть папка скилла (skill-skill, 00,
30-01). Что из того опыта остаётся верным:

* требования opencode к `SKILL.md` — `name` = имя папки скилла,
  `description` ≤ 1024 знаков и в кавычках при `: ` — общие, skill-skill
  00 и 30-06;
* PowerShell 5.1 не заходит в junction при `Get-ChildItem -Recurse`
  (нужен `-FollowSymlink` из PowerShell 6+) — пустой вывод не значит, что
  ссылка сломана, проверять `Test-Path` на файл; без прав администратора
  создаются только junction для папок и hardlink для файлов.
