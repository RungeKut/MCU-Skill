# Правила базы знаний MCU-Skill

**Общие правила — соседний скилл skill-skill, `knowledge/00_ПРАВИЛА.md`**:
что хранить, структура 10_/20_/30_/40_, шапка записи и статусы, добавление,
обновление и удаление, `SKILL.md` и установка, проверка целостности, язык.
Работа с репозиторием — там же, 40-02; здесь — 40-02 с особенностями
набора.

## Особенности набора

* **Что хранить:** поведение J-Link, STM32CubeProgrammer, компилятора,
  утилит и самих микроконтроллеров, расходящееся с документацией или
  интуицией; приёмы, доказавшие себя на реальном железе. Не хранить: то,
  что есть в документации SEGGER, ST, GCC и руководствах на чипы (ссылка и
  расхождение с реальностью — да); общие сведения о C, Python и make.
* **Изделие в базу не попадает** — ни названия, ни номера платы, ни цепей,
  компонентов, назначения выводов МК на плате, узлов, протоколов и команд
  изделия (40-02). Примеры — на отвлечённой «плате с Cortex-M4» или
  отладочных платах; имя чипа можно. Обезличивание — отдельный шаг после
  написания записи: пока пишешь, плата перед глазами.
* **Разделы:** `10_API` — J-Link, CLI ST, компилятор, регистры чипов;
  `20_ПРИЁМЫ` — порядок работы; `30_ГРАБЛИ` — что ломается (раздел «Как
  неправильно» обязателен); `40_СРЕДА` — установка, версии, зонды,
  репозиторий.
* **`applies_to` называет версию ПО и чип** (`J-Link V9.38a, GD32F470`):
  без них запись нельзя ни применить, ни перепроверить. `source` — способ
  («эксперимент на плате с GD32F470»), а не место.
* **Сменилась версия и поведение** — старое утверждение не стирается, а
  уходит в раздел «История» записи с указанием версии.
* **Знание о коде** дублируется одной-двумя фразами в docstring функции
  `mcukit/` со ссылкой на запись. Функция, полезная не только одному
  проекту, — в `mcukit`.
* **Порядок обращения:** `SKILL.md` → `INDEX.md` → файл базы → docstring
  `mcukit/` → документация (J-Link — `<папка J-Link>/Doc`, UM08001; ST —
  `STM32_Programmer_CLI.exe -h`, UM2237; регистры — руководство на чип, у
  GD32 — «User Manual») → эксперимент: чтение безопасно, запись — только с
  согласия человека и после `save()` (20-05); результат записать. При
  расхождении базы с документацией верить базе и перепроверять только при
  смене версии.
* **Непроверенное не выдавать за проверенное** — ни в коде, ни в отчёте,
  ни в базе. Первая версия `mcukit.stlink` заявляла «ядро не
  останавливается» по чтению статичных данных — растущий счётчик это
  опроверг (30-08, найдено 2026-09-25). Пока поведение не проверено
  способом, который мог бы его опровергнуть, — `не проверено`.
* **Язык:** термины русской инженерной практики (плата, вывод, прошивка,
  флеш); числа с единицами — «3,1 В», «16 КБ», «5 с»; адреса —
  `0x08000000`; код в примерах — рабочий целиком.
* Проверка: `python tools/check_docs.py --project "<папка проекта>"`
  (обёртка общей проверки; своё — `tools/kit_local.py`) и
  `python tests/test_build.py` (без железа) — 40-01.

## Версии: база собрана на J-Link V9.38a и GCC 10.3; ST-Link — на STM32CubeProgrammer 2.4.0

Всё, что записано до 25.09.2026, получено на:

* **SEGGER J-Link Software V9.38a**, зонд J-Link V9 (железо V9.50);
* **arm-none-eabi-gcc 10.3.1** (GNU Tools for STM32 из STM32CubeIDE
  1.12.1) и make оттуда же;
* чип **GD32F470** (Cortex-M4 r0p1) по SWD;
* Windows 10, Python 3.13.

Записи про `mcukit.stlink` (10-04, 20-04, 30-07, 40-03), добавленные
25.09.2026 на второй машине, — на:

* **STM32CubeProgrammer 2.4.0** (найден внутри STM32CubeIDE 1.3.0),
  зонд **ST-LINK/V2** (FW V2J32S7);
* чип **STM32L07x** (Cortex-M0+) по SWD;
* Windows 10, Python 3.12.

Поле `applies_to` записей называет их. **На другой версии J-Link или
STM32CubeProgrammer, другом компиляторе или другом чипе** запись
`проверено` читается как `не проверено`, пока не подтверждена там. Самое
вероятное расхождение:

* **скрипт производителя** в профиле чипа J-Link (что он делает при
  подключении, как проверяет защиту) — меняется от версии к версии ПО;
* **имена устройств** J-Link (`GD32F470VK` сейчас выбирает `GD32F470VKH6`);
* **адреса служебных регистров** — у другого семейства свои;
* **поведение binutils с путями** в другой сборке GCC;
* **разбор параметра `sn=`** у STM32_Programmer_CLI (30-07) — может быть
  исправлен в другой версии CLI.

Версии читаются без железа:

```python
import mcukit as mk
mk.jlink_version(), mk.gcc_version()      # ('V938a', '10.3.1')
mk.stlink_version()                       # '2.4.0'
```

Расхождение нашлось — сразу в базу, с обеими версиями в `applies_to`,
старое утверждение — в «Историю».
